# Cloudflare-hosted TFSA Tracker Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deploy the single-user TFSA Tracker at `https://tfsa.molinaristudios.com` as a password-protected Cloudflare Worker backed by Cloudflare D1, and safely migrate existing local data.

**Architecture:** The Next.js 16 application will run through vinext on Cloudflare Workers. Vite aliases every production import of `@/lib/db` to a Worker-safe Prisma D1 adapter while `next dev` retains the current `better-sqlite3` implementation. Authentication is a signed HttpOnly session cookie, and multi-record imports bypass Prisma transactions in favor of one native D1 `DB.batch()` call.

**Tech Stack:** Next.js 16.2.5, vinext, Vite, Cloudflare Workers, Cloudflare D1, Prisma 7, `@prisma/adapter-d1`, Tailwind CSS, Zod, Vitest 4, `@cloudflare/vitest-plugin`, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-08-27-cloudflare-hosted-tfsa-tracker-design.md`

## Global Constraints

- Deploy only to Cloudflare Workers; do not add GitHub Pages, a second frontend host, or a separate API origin.
- Serve production only at `https://tfsa.molinaristudios.com`; retain GitHub as source control and the deployment trigger.
- Keep all TFSA values as integer cents, label contribution room as estimated, and keep contribution-room calculations pure TypeScript.
- D1 holds `Account`, `Transaction`, `AnnualLimit`, and `UserSettings`; it must never store a password, CRA credential, bank/brokerage password, SIN, or account number.
- Keep Node/local SQLite code unreachable from the Worker bundle. `npm run dev` continues to use the local `prisma/dev.db`; Worker tests use locally simulated D1.
- Protect every page, server action, and route handler with the shared session verifier. A request must be authorized server-side even if `src/proxy.ts` was bypassed.
- Worker secrets are named `TFSA_PASSWORD` and `TFSA_SESSION_SECRET`; neither may appear in a source file, test fixture, GitHub Action, or committed `.env` file.
- Parse an entire CSV or JSON backup before emitting any D1 statement. A production import is one `DB.batch()` call, with input capped at 5 MiB, 2,000 accounts, and 10,000 transactions.
- Preserve existing transaction CSV import/export. The full JSON backup adds settings and stable record metadata for the one-time migration.
- Every Codex-generated commit message includes `[GENERATED]`.
